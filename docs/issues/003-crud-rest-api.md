# CRUD REST API для существующих сущностей

## Описание

Как разработчик, я хочу иметь полноценный REST API для управления основными сущностями системы, чтобы клиентские приложения могли взаимодействовать с данными через стандартные HTTP-методы.

## Технический контекст

Сейчас в приложении большинство эндпоинтов — это MVC-контроллеры, возвращающие HTML. Единственный JSON REST эндпоинт — `GET /vets`. Необходимо реализовать полноценный CRUD REST API для всех ключевых сущностей домена.

Требования к реализации:
- Все эндпоинты возвращают и принимают **JSON**
- Данные передаются через **DTO**, сущности JPA не используются напрямую в ответах/запросах
- Для маппинга между сущностями и DTO используется **MapStruct**
- Базовый URL для всех REST эндпоинтов: `/rest`
- Коллекции возвращаются в flat виде (массив ID)

## Сущности и эндпоинты

### Owner (`/rest/owners`)

| Метод  | URL                  | Описание                        |
|--------|----------------------|---------------------------------|
| GET    | `/rest/owners`        | Список всех владельцев          |
| GET    | `/rest/owners/{id}`   | Получить владельца по ID        |
| POST   | `/rest/owners`        | Создать владельца               |
| PUT    | `/rest/owners/{id}`   | Обновить данные владельца       |
| DELETE | `/rest/owners/{id}`   | Удалить владельца               |

## Ограничения и допущения

- Существующие MVC-контроллеры не удаляются и не изменяются — REST API добавляется параллельно
- Существующий `GET /vets` остаётся без изменений для обратной совместимости
- Пагинация для списочных эндпоинтов — опционально, на усмотрение разработчика
