# Шаблон рабочего расписания ветеринаров

## Описание

Как администратор клиники, я хочу создавать именованные шаблоны рабочих расписаний и назначать их ветеринарам, чтобы автоматически генерировать конкретное расписание на нужный период.

## Бизнес-контекст

Большинство ветеринаров клиники работают по фиксированному недельному графику: стандартная пятидневка, первая или вторая смена, работа по субботам. Вместо того чтобы заполнять конкретные даты вручную, администратор создаёт шаблон один раз и затем использует его для генерации рабочего расписания на нужный период (неделю, месяц и т.д.). Шаблон описывает типовой недельный цикл без привязки к конкретным датам.

## Термины

| Термин | Определение |
|---|---|
| **Шаблон расписания** | Именованный набор правил, описывающих повторяющийся недельный рабочий цикл |
| **Строка шаблона** | Одно правило внутри шаблона: диапазон дней недели + один или несколько временных интервалов |
| **Диапазон дней** | Два дня недели через дефис, например `MON-FRI`, `SAT-SAT` |
| **Временной интервал** | Пара `HH:mm-HH:mm`, описывающая один непрерывный рабочий отрезок |

## Формат строки шаблона

Строка шаблона записывается в одну текстовую строку:

```
<DAY_FROM>-<DAY_TO> <TIME_FROM>-<TIME_TO>[,<TIME_FROM>-<TIME_TO>...]
```

Примеры:

| Строка | Смысл |
|---|---|
| `MON-FRI 09:00-13:00,14:00-18:00` | Пн–Пт, первая и вторая половина дня с обедом |
| `MON-FRI 14:00-22:00` | Пн–Пт, вторая смена |
| `SAT-SAT 09:00-15:00` | Только суббота |

Правила формата:
- Дни недели: `MON`, `TUE`, `WED`, `THU`, `FRI`, `SAT`, `SUN` (ISO-порядок)
- `DAY_FROM` должен быть не позже `DAY_TO` в недельном цикле
- Время — 24-часовой формат `HH:mm`
- Конец каждого временного интервала строго позже его начала
- Интервалы в одной строке перечисляются через запятую без пробелов
- Интервалы в одной строке **не должны перекрываться** и должны идти в хронологическом порядке

## Требования

### Шаблон расписания

- Шаблон имеет **уникальное название** в рамках клиники (не привязан к конкретному ветеринару).
- Шаблон содержит **одну или несколько строк** — каждая описывает отдельный режим работы внутри недельного цикла.
- Примеры готовых шаблонов, которые должны поддерживаться:
  - **«Стандарт»**: `MON-FRI 09:00-13:00,14:00-18:00`
  - **«Вторая смена»**: `MON-FRI 14:00-22:00`
  - **«Суббота»**: `SAT-SAT 09:00-15:00`
  - **«Полная неделя»**: `MON-FRI 09:00-13:00,14:00-18:00` + `SAT-SAT 09:00-15:00`

### Строки шаблона

- Каждая строка шаблона хранится в виде текстового значения в формате, описанном выше, и разбирается системой при сохранении.
- При сохранении система **валидирует** строку: формат, корректность дней и времени, отсутствие перекрытий внутри строки.
- Строки внутри одного шаблона **не валидируются на пересечение** между собой — это допустимо (например, один день может попасть в несколько строк).

### Привязка шаблона к ветеринару

- Ветеринару назначается **один шаблон по умолчанию** (ссылка, не копия).
- Смена шаблона по умолчанию не изменяет сам шаблон и не влияет на других ветеринаров, использующих тот же шаблон.

### Генерация рабочего расписания из шаблона

- Администратор запускает генерацию вручную — как правило, раз в месяц.
- При запуске администратор указывает:
  - **Ветеринар**: конкретный ветеринар, для которого генерируется расписание.
  - **Период**: дата начала — дата окончания.
  - **Шаблон** (необязательно): если не указан, используется шаблон по умолчанию ветеринара.
- Результатом генерации является набор конкретных рабочих элементов (дата + временной интервал), который становится рабочим расписанием ветеринара на указанный период.
- Если шаблон не указан и у ветеринара нет шаблона по умолчанию — система возвращает ошибку.

## Модель данных

### Шаблон расписания

Именованный шаблон, описывающий типовой недельный рабочий цикл. Является общим ресурсом клиники — не привязан к конкретному ветеринару.

| Поле           | Тип          | Обязательное      | Описание                                     |
|----------------|--------------|-------------------|----------------------------------------------|
| Название       | Строка       | Да                | Уникальное название шаблона в рамках клиники |
| Строки шаблона | Список строк | Да (минимум одна) | Правила рабочего цикла                       |

### Строка шаблона

Одно правило внутри шаблона: описывает, в какие дни недели и в какие временные интервалы ветеринар работает.

| Поле                | Тип                        | Обязательное      | Описание                                                                               |
|---------------------|----------------------------|-------------------|----------------------------------------------------------------------------------------|
| Исходная строка     | Строка                     | Да                | Полная запись правила в текстовом формате, например `MON-FRI 09:00-13:00,14:00-18:00` |
| День начала         | День недели                | Да                | Начало диапазона рабочих дней (MON–SUN)                                                |
| День окончания      | День недели                | Да                | Конец диапазона рабочих дней (MON–SUN); не раньше дня начала                          |
| Временные интервалы | Список пар (начало, конец) | Да (минимум один) | Упорядоченный список рабочих отрезков дня; интервалы не перекрываются                  |

### Ветеринар

| Поле                  | Тип                          | Обязательное | Описание                                                                                   |
|-----------------------|------------------------------|--------------|--------------------------------------------------------------------------------------------|
| Шаблон по умолчанию   | Ссылка на шаблон расписания  | Нет          | Шаблон, используемый при генерации расписания, если другой шаблон не указан явно          |

## Ограничения и допущения

- Шаблон описывает **недельный цикл** и не привязан к конкретным датам или периодам действия.
- Шаблон является **общим ресурсом клиники**: один шаблон может использоваться несколькими ветеринарами одновременно.
- Изменение строк шаблона не затрагивает уже сгенерированные расписания — только будущие генерации.
- Генерация расписания из шаблона описана в данной задаче; проверка визитов на соответствие расписанию описана в задаче 001.

## Пользовательские сценарии

### Сценарий 1: Создание шаблона «Стандарт»

**Дано:** В системе нет ни одного шаблона расписания  
**Когда:** Администратор создаёт шаблон с названием «Стандарт» и добавляет одну строку: `MON-FRI 09:00-13:00,14:00-18:00`  
**Тогда:** Шаблон «Стандарт» сохраняется, строка проходит валидацию формата

### Сценарий 2: Создание многострочного шаблона «Полная неделя»

**Дано:** В системе нет шаблона «Полная неделя»  
**Когда:** Администратор создаёт шаблон «Полная неделя» с двумя строками:
1. `MON-FRI 09:00-13:00,14:00-18:00`
2. `SAT-SAT 09:00-15:00`

**Тогда:** Шаблон сохраняется с двумя строками; каждая строка валидируется независимо

### Сценарий 3: Отклонение строки с некорректным форматом

**Дано:** Администратор создаёт новый шаблон  
**Когда:** Он добавляет строку `MONDAY-FRIDAY 9:00-18:00` (неверные названия дней и формат времени)  
**Тогда:** Система отклоняет сохранение с описанием ошибки формата; шаблон не создаётся

### Сценарий 4: Отклонение строки с перекрывающимися интервалами

**Дано:** Администратор создаёт новый шаблон  
**Когда:** Он добавляет строку `MON-FRI 09:00-14:00,13:00-18:00` (интервалы 09:00–14:00 и 13:00–18:00 перекрываются)  
**Тогда:** Система отклоняет сохранение с сообщением о перекрытии временных интервалов

### Сценарий 5: Назначение шаблона ветеринару

**Дано:** Шаблон «Стандарт» существует; у ветеринара Иванова нет шаблона по умолчанию  
**Когда:** Администратор назначает ветеринару Иванову шаблон «Стандарт» как шаблон по умолчанию  
**Тогда:** Ветеринар Иванов получает шаблон «Стандарт» в качестве шаблона по умолчанию

### Сценарий 6: Смена шаблона по умолчанию у ветеринара

**Дано:** У ветеринара Иванова назначен шаблон «Стандарт» (по умолчанию); в системе есть шаблон «Вторая смена»  
**Когда:** Администратор назначает ветеринару Иванову шаблон «Вторая смена» как новый шаблон по умолчанию  
**Тогда:** Шаблоном по умолчанию у Иванова становится «Вторая смена»; сам шаблон «Стандарт» не изменяется

### Сценарий 7: Генерация расписания на неделю

**Дано:** У ветеринара Иванова шаблон по умолчанию — «Стандарт» (`MON-FRI 09:00-13:00,14:00-18:00`)  
**Когда:** Администратор запускает генерацию расписания для Иванова на период 14–20 апреля 2025 года  
**Тогда:** Система создаёт рабочие элементы для Пн–Пт (14–18 апреля): для каждого дня два элемента — 09:00–13:00 и 14:00–18:00; суббота (19 апреля) и воскресенье (20 апреля) остаются без элементов

### Сценарий 8: Генерация расписания из многострочного шаблона

**Дано:** У ветеринара Иванова шаблон по умолчанию — «Полная неделя» (`MON-FRI 09:00-13:00,14:00-18:00` + `SAT-SAT 09:00-15:00`)  
**Когда:** Администратор запускает генерацию расписания для Иванова на период 14–20 апреля 2025 года  
**Тогда:** Система создаёт рабочие элементы для Пн–Пт (09:00–13:00 и 14:00–18:00) и для субботы 19 апреля (09:00–15:00); воскресенье остаётся без элементов

### Сценарий 9: Отклонение генерации при отсутствии шаблона

**Дано:** У ветеринара Иванова нет шаблона по умолчанию  
**Когда:** Администратор пытается запустить генерацию расписания для Иванова, не указывая шаблон  
**Тогда:** Система отклоняет запрос с сообщением об отсутствии шаблона по умолчанию

### Сценарий 10: Удаление шаблона, назначенного ветеринару

**Дано:** Шаблон «Стандарт» назначен одному или нескольким ветеринарам как шаблон по умолчанию  
**Когда:** Администратор пытается удалить шаблон «Стандарт»  
**Тогда:** Система отклоняет удаление с сообщением о том, что шаблон используется ветеринарами
