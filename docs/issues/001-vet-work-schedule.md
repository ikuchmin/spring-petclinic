# Рабочее расписание ветеринаров

## Описание

Как администратор клиники, я хочу управлять рабочими расписаниями ветеринаров, чтобы видеть, когда каждый ветеринар доступен для приёма.

## Бизнес-контекст

Сейчас в системе нет информации о рабочем графике ветеринаров. Администратор не может определить, в какие дни и часы конкретный ветеринар принимает пациентов. Это приводит к тому, что записи на приём создаются без учёта реального графика работы.

## Требования

### Расписание

- У каждого ветеринара может быть **несколько расписаний** (например, «Основное», «Летний график», «Дежурства»).
- Каждое расписание имеет **название** для идентификации.
- Одно из расписаний ветеринара может быть помечено как **для записи**. В каждый момент времени у ветеринара не более одного расписания по умолчанию.

### Элементы расписания

- Расписание состоит из **отдельных элементов** — записей о рабочих сменах.
- Каждый элемент содержит:
  - **Дату** — конкретный рабочий день
  - **Время начала** — начало рабочей смены
  - **Время окончания** — конец рабочей смены
- Время окончания должно быть строго позже времени начала.
- На один день может приходиться **несколько элементов** — например, для учёта перерыва на обед (09:00–13:00 и 14:00–18:00). Промежутки между элементами считаются нерабочим временем.

### Валидация пересечений

- В рамках одного расписания **не допускается пересечение элементов по времени**.
- Пересечением считается ситуация, когда два элемента приходятся на одну дату и их временные интервалы накладываются друг на друга.
- При попытке добавить элемент, пересекающийся с существующим, система должна отклонить запрос с информативным сообщением об ошибке.

### Поля визита

- Визит содержит **время начала** и **время окончания** (в рамках одной даты).
- Время окончания должно быть строго позже времени начала.

### Проверка при добавлении визита

- При создании визита система должна проверить, что у назначенного ветеринара есть расписание **для записи** с рабочим элементом, полностью покрывающим интервал визита (от начала до окончания). Если расписание отсутствует или рабочий элемент не покрывает весь интервал — визит отклоняется.
- Система должна проверить, что у ветеринара **нет других визитов**, пересекающихся по времени с создаваемым. Пересечением считается любое наложение интервалов. Если конфликт обнаружен — визит отклоняется с сообщением о занятости ветеринара.

## Пользовательские сценарии

### Сценарий 1: Создание основного расписания

**Дано:** В системе зарегистрирован ветеринар Иванов И.И., у него ещё нет расписаний
**Когда:** Администратор создаёт новое расписание с названием «Основное» для ветеринара Иванова и назначает его расписанием для записи
**Тогда:** Расписание «Основное» создаётся без элементов и помечается как расписание для записи

### Сценарий 2: Добавление нескольких элементов в один день с перерывом на обед

**Дано:** У ветеринара Иванова есть расписание «Основное» (для записи), без элементов
**Когда:** Администратор добавляет в «Основное» два элемента на 15 апреля: 09:00–13:00 и 14:00–18:00
**Тогда:** Оба элемента добавляются в расписание «Основное». Интервал 13:00–14:00 остаётся нерабочим (обед).

### Сценарий 3: Отклонение пересекающегося элемента в основном расписании

**Дано:** В расписании «Основное» (для записи) ветеринара Иванова уже есть элементы на 15 апреля: 09:00–13:00 и 14:00–18:00
**Когда:** Администратор добавляет в «Основное» элемент: 15 апреля, 12:00–15:00
**Тогда:** Система отклоняет запрос с сообщением о пересечении с существующим элементом

### Сценарий 4: Назначение расписания по умолчанию

**Дано:** У ветеринара Иванова есть два расписания: «Основное» (для записи) и «Летний график»
**Когда:** Администратор назначает «Летний график» расписанием для записи
**Тогда:** «Летний график» становится расписанием для записи, «Основное» перестаёт быть таковым

### Сценарий 5: Успешное создание визита в рабочее время

**Дано:** У ветеринара Иванова есть расписание «Основное» (для записи) с элементами на 15 апреля: 09:00–13:00 и 14:00–18:00. На 15 апреля у Иванова нет других визитов.
**Когда:** Администратор создаёт визит к ветеринару Иванову на 15 апреля с 10:00 до 11:00
**Тогда:** Визит создаётся успешно — интервал 10:00–11:00 полностью покрыт рабочим элементом 09:00–13:00

### Сценарий 6: Отклонение визита во время обеда

**Дано:** У ветеринара Иванова есть расписание «Основное» (для записи) с элементами на 15 апреля: 09:00–13:00 и 14:00–18:00
**Когда:** Администратор создаёт визит к ветеринару Иванову на 15 апреля с 12:30 до 13:30
**Тогда:** Система отклоняет запрос с сообщением, что интервал визита выходит за пределы рабочего времени (13:00–13:30 попадает в перерыв)

### Сценарий 7: Отклонение визита при конфликте с другим визитом

**Дано:** У ветеринара Иванова есть расписание «Основное» (для записи) с элементом: 15 апреля, 09:00–17:00. На 15 апреля уже записан визит с 10:00 до 11:00.
**Когда:** Администратор создаёт ещё один визит к ветеринару Иванову на 15 апреля с 10:30 до 11:30
**Тогда:** Система отклоняет запрос с сообщением о конфликте с существующим визитом (интервалы 10:00–11:00 и 10:30–11:30 пересекаются)

### Сценарий 8: Отклонение визита при отсутствии расписания

**Дано:** У ветеринара Иванова нет расписания по умолчанию
**Когда:** Администратор создаёт визит к ветеринару Иванову на 15 апреля с 10:00 до 11:00
**Тогда:** Система отклоняет запрос с сообщением, что у ветеринара не задано рабочее расписание

### Сценарий 9: Удаление расписания

**Дано:** У ветеринара Иванова есть расписание «Летний график» с тремя элементами, оно не является расписанием для записи
**Когда:** Администратор удаляет расписание «Летний график»
**Тогда:** Расписание «Летний график» и все его элементы удаляются из системы, расписание «Основное» остаётся без изменений

## Модель данных

### Расписание ветеринара

Именованный набор рабочих элементов, описывающих конкретные рабочие смены ветеринара.

| Поле              | Тип      | Обязательное | Описание                                                          |
|-------------------|----------|--------------|-------------------------------------------------------------------|
| Название          | Строка   | Да           | Название расписания, например «Основное» или «Летний график»      |
| Для записи        | Признак  | Да           | Помечает расписание как используемое при проверке доступности; у ветеринара не более одного такого расписания |
| Элементы          | Список   | Нет          | Рабочие смены, входящие в расписание                              |

### Элемент расписания

Одна рабочая смена в конкретный день.

| Поле           | Тип         | Обязательное | Описание                                                            |
|----------------|-------------|--------------|---------------------------------------------------------------------|
| Дата           | Дата        | Да           | Конкретный рабочий день                                             |
| Время начала   | Время       | Да           | Начало рабочей смены (формат HH:mm)                                 |
| Время окончания | Время      | Да           | Конец рабочей смены (формат HH:mm); строго позже времени начала     |

### Ветеринар — связь с расписаниями

| Поле        | Тип           | Обязательное | Описание                                              |
|-------------|---------------|--------------|-------------------------------------------------------|
| Расписания  | Список        | Нет          | Все расписания ветеринара; может быть несколько       |

### Визит

| Поле             | Тип   | Обязательное | Описание                                                              |
|------------------|-------|--------------|-----------------------------------------------------------------------|
| Дата             | Дата  | Да           | Дата визита                                                           |
| Время начала     | Время | Да           | Время начала визита (формат HH:mm)                                    |
| Время окончания  | Время | Да           | Время окончания визита (формат HH:mm); строго позже времени начала    |

## Ограничения и допущения

- Расписания разных ветеринаров не зависят друг от друга — валидация пересечений действует только внутри одного расписания одного ветеринара.
- Элементы расписания привязаны к конкретным датам (не к дням недели).
